# อีเมลเตือนงานจาก TaskFlow

TaskFlow ส่งสรุปงานที่ยังไม่เสร็จและครบกำหนดแล้วผ่าน SMTP ของเซิร์ฟเวอร์เอง ผู้ใช้ไม่ต้องสร้าง API Key หรือตั้งค่า n8n

## เงื่อนไข

- ผู้ดูแลตั้ง `SMTP_USER` และ `SMTP_PASS` ใน `.env` แล้วเปิดเซิร์ฟเวอร์ใหม่ ใช้ชุดเดียวกับอีเมลลืมรหัสผ่านและยืนยันอีเมล
- ผู้ใช้ยืนยันอีเมลแล้ว บัญชีใหม่จะเปิดรับอีเมลเตือนงานอัตโนมัติหลังยืนยัน
- เซิร์ฟเวอร์ TaskFlow ต้องเปิดอยู่ การตรวจรอบหลัง 07:00 น. เวลา Asia/Bangkok จะส่งเมลสรุปงานค้างให้บัญชีที่มีงาน ไม่ส่งเมื่อไม่มีงานค้าง
- ค่าเริ่มต้น `EMAIL_REMINDERS_ENABLED=true` หากรันหลาย instance ให้ตั้ง `false` บนตัวอื่น และให้ตัวส่งเมลมีเพียงตัวเดียว
- งานที่ยังค้างจะถูกเตือนอีกครั้งในวันถัดไป หนึ่งบัญชีได้รับสรุปได้สูงสุดหนึ่งฉบับต่อวัน งานที่เพิ่มหลังอีเมลของวันนั้นจะรวมในรอบวันถัดไป

หากเว็บปิดในเวลา 07:00 น. แล้วเปิดภายหลังในวันเดียวกัน เซิร์ฟเวอร์จะตรวจและส่งงานที่ยังไม่ได้เตือนของวันนั้นเมื่อเริ่มทำงานใหม่ การส่งล้มเหลวจะลองใหม่หลังช่วงพักประมาณ 15 นาที

## ทดสอบและดูประวัติ

รัน `npm.cmd run mail:check` เพื่อตรวจการเชื่อมต่อ SMTP โดยยังไม่ส่งข้อความ ดูสถานะในหน้า **การเชื่อมต่อ** และประวัติในหัวข้อ **ประวัติอีเมลเตือนงาน** การทดสอบหน่วยใช้ SMTP จำลองและฐานข้อมูลชั่วคราว จึงไม่ส่งเมลให้บัญชีจริง

หากเคยเปิด n8n workflow เตือนงาน ให้ปิด workflow นั้นเมื่อใช้ระบบใหม่นี้ เพื่อเลี่ยงการส่งจากสองระบบในช่วงเดียวกัน API Key เดิมยังใช้ได้สำหรับการเชื่อมต่อภายนอกแบบเลือกใช้

SMTP ตอบรับข้อความไม่ได้รับประกันว่าเมลถึง inbox; ผู้รับอาจพบใน spam หรือผู้ให้บริการอาจ bounce ข้อความ หาก SMTP รับเมลแล้วเซิร์ฟเวอร์หยุดก่อนบันทึกประวัติ อาจมีการส่งซ้ำเมื่อเริ่มใหม่ และหากใช้ Gmail ส่วนตัวกับผู้ใช้จำนวนมากอาจชนโควตาผู้ส่ง ควรใช้ผู้ให้บริการอีเมลธุรกรรมเมื่อเปิดเว็บให้คนจำนวนมากใช้งาน
