# TaskFlow

เว็บจัดการงานส่วนตัวขนาดเล็กสำหรับเรียนรู้ **React + Tailwind + Hono + SQL** ใน monorepo พร้อม JWT login และ API key สำหรับ n8n

ธีมสีแดง ขาว และเทาตามไอคอนที่ผู้ใช้ให้มา พร้อมภาพสถานที่เป็นพื้นหลังจาง ๆ ใต้เนื้อหา ชื่อระบบเป็น TaskFlow

## เริ่มใช้งาน

ต้องมี Node.js **22.13 ขึ้นไป** แนะนำ Node.js รุ่น LTS ที่ยังได้รับการสนับสนุน ใช้ SQLite ที่มาพร้อม Node จึงไม่ต้องติดตั้งฐานข้อมูลแยก

```powershell
npm.cmd install
npm.cmd run setup
npm.cmd run db:seed
npm.cmd run dev
```

เปิด **http://localhost:5173** สำหรับเว็บ และ **http://localhost:3000/api/health** สำหรับตรวจ API

- บัญชีเดโม: `demo@taskflow.local`
- รหัสผ่านเดโม: `TaskFlow!2026`
- สมัครบัญชีใหม่ได้ รหัสผ่าน8–16 ตัวอักษร
- `npm run setup` สร้าง `.env` และ JWT secret แบบสุ่มครั้งแรก โดยไม่ทับไฟล์เดิม
- `npm run db:seed` สร้างข้อมูลตัวอย่างครั้งแรก โดยไม่ลบงานเดิม
- ฐานข้อมูลจริงอยู่ที่ `data/taskflow.sqlite` และไม่เข้า Git
- บัญชีเดโมใช้เรียนรู้ในเครื่องเท่านั้น หากต้องส่งอีเมลจริง ให้สมัครด้วยอีเมลที่รับข้อความได้

## สิ่งที่ทำได้

**วันนี้ควรทำอะไร** แสดงงานที่ครบกำหนดหรือเลยกำหนดก่อน และให้เลือกช่วงเวลาลงมือทำในแต่ละวัน ระบบกันช่วงเวลาทับกันและแสดงช่วงที่วางแผนในปฏิทินงาน แต่ยังไม่ส่งการแจ้งเตือนเมื่อถึงเวลาที่วางไว้

**บันทึกการทำงาน** จดงานและผลที่ได้รายวันพร้อมลิงก์หลักฐาน ดูรายสัปดาห์ สร้างข้อความสรุปที่แก้ไขและคัดลอกได้ และนำข้อมูล 5 วันแรกของสัปดาห์ไปร่าง สก.09 หลังยืนยัน รายงานใช้เฉพาะข้อมูลที่บันทึกใน TaskFlow และยังต้องตรวจความถูกต้องก่อนนำไปส่ง

**ทำงานร่วมกัน** เจ้าของโปรเจกต์เพิ่มสมาชิกที่สมัคร TaskFlow แล้วด้วยอีเมล กำหนดสิทธิ์ดูอย่างเดียวหรือแก้ไขได้ สมาชิกดูงานในบอร์ดร่วมกัน เพิ่มงาน เปลี่ยนสถานะ และมอบหมายผู้รับผิดชอบตามสิทธิ์ได้ สมาชิกออกจากโปรเจกต์เองได้ การแชร์มีผลทันทีและยังไม่มีขั้นตอนตอบรับคำเชิญ

**GitHub → งาน** ตั้งค่าแต่ละโปรเจกต์ให้สร้างงานความสำคัญสูงเมื่อ pipeline ที่ติดตามเปลี่ยนเป็นสถานะล้มเหลว ระบบสร้างหนึ่งงานต่อ run และทำงานเมื่อเปิด/รีเฟรชการแจ้งเตือน GitHub ไม่ใช่ webhook ตลอดเวลา

**โปรเจกต์** จัดกลุ่มงาน ปฏิทิน และ GitHub repository ภายใต้ชื่อเดียวกัน งานเดิมยังอยู่ใน “ยังไม่จัดโปรเจกต์” ตั้งค่าให้เตือน pipeline ล้มเหลวเฉพาะ repository หรือ Workflow ID ได้ และเปิดหน้า GitHub ของโปรเจกต์นั้นโดยตรง งานแต่ละชิ้นแนบ GitHub Issue/PR แล้วดูชื่อกับสถานะที่ GitHub รายงานได้ (ต้องเพิ่มสิทธิ์ Issues/Pull requests read ให้ App)

**สก.09 จากงานที่บันทึกไว้** เลือกช่วง 5 วันแล้วกดนำงานจากปฏิทินมาช่วยกรอก ระบบแสดงตัวอย่างก่อน และให้เลือกเติมเฉพาะช่องว่างหรือแทนที่ช่องงาน ผลการฝึกงานยังให้ผู้ใช้ตรวจและเขียนเอง

**ข้อมูลส่วนตัว** มีลิงก์ยืนยันอีเมลอายุ 15 นาที การเปลี่ยนอีเมลจะยังใช้อีเมลเดิมจนกว่าจะยืนยันที่อยู่ใหม่ ดาวน์โหลดข้อมูลบัญชีเป็น JSON หรือลบบัญชีหลังกรอกอีเมล คำยืนยัน และรหัสผ่าน (บัญชี Google ต้องเพิ่งลงชื่อเข้าใช้) ระบบมีสคริปต์สำรองฐานข้อมูลและตรวจการกู้คืน ดู [คู่มือข้อมูลและการสำรอง](docs/account-data.md)

เมนู **บันทึก สก.09** กรอกชื่อ รหัสนิสิต บริษัท แผนก และบันทึกงาน/ผลการฝึกงาน 5 วัน เลือกวันเริ่มหรือวันสิ้นสุดแล้วระบบปรับช่วงให้ติดกัน 5 วัน เลือกเวลาครั้งเดียวใช้ทั้งตาราง (เริ่มต้น 08:00–17:00) ดูตัวอย่างและดาวน์โหลด PDF ภาษาไทยขนาด A4 ได้ โดยคงตรา หัวแบบฟอร์ม และช่องลงนามว่างตามเอกสารอ้างอิง ข้อมูลสร้าง PDF ใน browser และไม่ส่งไปบริการภายนอก เก็บร่างล่าสุด 1 ฉบับต่อบัญชีในฐานข้อมูลโดยอัตโนมัติ พร้อมปุ่มบันทึกร่าง กรอกไม่ครบก็เก็บไว้ได้ เปิดต่อจากเครื่องอื่นได้ และตรวจ version ป้องกันการเขียนทับจากหลายแท็บ ข้อความยาวจะขยายแถวและอาจต่อหน้าใหม่โดยไม่ตัดข้อความ

หน้า **ปฏิทินงาน** แสดงปฏิทินขนาดใหญ่ เริ่มจากเดือนปัจจุบันตามเวลาไทย เลื่อนดูเดือนก่อนหน้า/ถัดไปและกลับเดือนปัจจุบันได้ งานอยู่ในวันครบกำหนดและใช้สีตามความสำคัญ รวมงานเสร็จแล้วด้วยเครื่องหมายขีดฆ่า กดงานเพื่อแก้ไข หรือกด + ในวันที่ต้องการเพื่อเพิ่มงานพร้อมวันส่งที่เลือก งานไม่ระบุวันส่งดูได้ในงานทั้งหมด บนมือถือเลื่อนตารางแนวนอนได้

รายการงานใช้สีส้มแดง/เหลืองอ่อน/ฟ้าอ่อนสำหรับความสำคัญสูง/ปกติ/ต่ำ เรียงงานที่ยังไม่เสร็จตามวันครบกำหนดใกล้สุดก่อน ถ้าวันเดียวกันเรียงสูง → ปกติ → ต่ำ งานไม่มีวันส่งอยู่ถัดจากงานที่มีวันส่ง และงานเสร็จแล้วอยู่ท้ายรายการ

ไอคอนกระดิ่งแสดงการแจ้งเตือนที่ยังไม่อ่าน สร้างรอบรายวันตั้งแต่ **07:00 น. ตามเวลาไทย** สำหรับงานที่ยังไม่เสร็จและเลยกำหนด ต้องส่งวันนี้ หรือภายใน 3 วันถัดไป กดรายการเพื่ออ่านและเปิดงาน หรือกดอ่านทั้งหมด การอ่านเก็บใน SQLite จึงไม่กลับมาเมื่อรีเฟรชหน้า และไม่เปลี่ยนสถานะงาน รอบวันถัดไปเตือนงานที่ยังค้างอีกครั้งและแทนรอบเก่า ระบบสร้างรอบเมื่อ browser ขอข้อมูลครั้งแรกหลัง 07:00 (ตรวจทุก 1 นาทีขณะเปิดเว็บ) หากปิดเครื่องจะสร้างเมื่อกลับมาเปิด ไม่ใช่ push notification นอกเว็บ งานเพิ่มหลังสร้างรอบแล้วจะเข้ารอบวันถัดไป การแจ้งเตือนนี้แยกจากอีเมล n8n และไม่ต้องตั้ง n8n เพิ่ม

เมนู **ตั้งค่าบัญชี** แก้ชื่อ ชื่อเล่น เบอร์โทร และอีเมลได้ ชื่อเล่นจะใช้แสดงแทนชื่อปกติเมื่อกรอกไว้ การเปลี่ยนอีเมลต้องยืนยันรหัสผ่านปัจจุบัน ระบบจะส่งลิงก์ไปยังอีเมลใหม่ และยังใช้อีเมลเดิมจนกว่าจะกดยืนยัน

รูปโปรไฟล์รองรับ JPG, PNG, GIF และ WebP ไม่เกิน **2 MB** เลือกจากเครื่องหรือนำเข้าจาก URL ของไฟล์ภาพโดยตรงได้ รูปจากลิงก์ต้องอนุญาต CORS ให้ browser ดาวน์โหลด หากต้นทางบล็อกให้บันทึกไฟล์ลงเครื่องแล้วอัปโหลดแทน รูปถูกเก็บใน SQLite และเปิดได้เฉพาะเจ้าของบัญชี สามารถลบหรือเปลี่ยนใหม่ได้

เพิ่ม แก้ไข ลบงาน กำหนดวันส่งและความสำคัญ เปลี่ยนสถานะเป็นยังไม่เริ่ม/กำลังทำ/เสร็จแล้ว ค้นหาและกรองงาน ดูสรุปงานและงานเลยกำหนด แต่ละบัญชีเห็นเฉพาะงานของตนเอง

สร้าง API key สำหรับ n8n คัดลอกได้ครั้งเดียว ดูวันหมดอายุ ยกเลิก key และดูประวัติแจ้งเตือนได้ n8n เป็นส่วนเสริม เว็บใช้งานได้โดยไม่ต้องเปิด n8n

ลืมรหัสผ่านได้จากหน้า login เมื่อกำหนด Gmail SMTP แล้ว ระบบส่งลิงก์อายุ 5 นาที ใช้ได้ครั้งเดียว ตั้งรหัสใหม่ 8–16 ตัวอักษรและเพิกถอน session เดิมทั้งหมด ฟีเจอร์นี้ส่งจาก backend โดยตรง ไม่ต้องเปิด n8n

## Google และ GitHub

เข้าสู่ระบบด้วย Google หรือเชื่อม Google กับบัญชีเดิมในตั้งค่าบัญชี จากนั้นเชื่อม GitHub และติดตั้ง GitHub App ให้ repository ที่ต้องการ เมนู **GitHub** ใช้ดูไฟล์/โค้ด, commit และ diff, workflow/run, jobs/steps และ check reports พร้อมสั่งรัน รันซ้ำ หรือยกเลิกหลังยืนยันคำสั่ง อ่าน [คู่มือตั้งค่าและใช้งาน Google + GitHub](docs/google-github.md) ก่อนใช้งานครั้งแรก

## ตั้งค่าอีเมลลืมรหัสผ่าน

```powershell
npm run setup:email
```

คำสั่งเติมตัวแปรอีเมลที่ขาดใน `.env` โดยไม่ทับค่าที่มีอยู่ ให้ใส่ `SMTP_USER` เป็น Gmail ผู้ส่ง และ `SMTP_PASS` เป็น **Google App Password** ของบัญชีนั้น ใช้ค่าเริ่มต้น `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`, `SMTP_SECURE=true` พร้อม `APP_PUBLIC_URL=http://localhost:5173` สำหรับ dev หากใช้ `npm start` หลัง build ให้เปลี่ยน URL เป็น `http://localhost:3000` หรือ domain HTTPS จริง แล้วเปิด server ใหม่

ตรวจ SMTP login แบบไม่ส่งเมลด้วย `npm run mail:check` จากนั้นทดลองจากปุ่ม **ลืมรหัสผ่าน?** ด้วยบัญชีที่สมัครด้วยอีเมลรับจริง บัญชีเดโม `.local` รับอีเมลไม่ได้ การส่งผ่าน Gmail จริงต้องตั้ง credential ของคุณก่อน อ่านวิธีเปิด 2-Step Verification สร้าง App Password และแก้ปัญหาใน [คู่มือ Gmail SMTP และลืมรหัสผ่าน](docs/password-reset-gmail.md) อย่าใส่รหัสผ่าน Gmail ปกติหรือส่ง secret ในแชต

## โครงสร้าง

```text
apps/
  web/                  React + Tailwind + Vite
  api/src/
    app.ts              ประกอบ routes และ middleware
    auth.ts             สมัคร/เข้า/ออกจากระบบ ตรวจ JWT และ session
    password-reset.ts   ขอลิงก์และตั้งรหัสผ่านใหม่แบบใช้ครั้งเดียว
    mail.ts             ส่งอีเมล reset ผ่าน SMTP และสร้าง URL ที่ตั้งไว้
    social.ts           Google login และเชื่อมบัญชี Google/GitHub
    social-config.ts    OAuth config, ตรวจ Google ID token, เข้ารหัส GitHub token
    github.ts           GitHub repositories, commits, Actions และ checks
    tasks.ts            CRUD และสรุปงาน
    integrations.ts     API key, due tasks และประวัติแจ้งเตือน
    security.ts         scrypt, JWT, SHA-256
    db.ts / schema.sql  เปิด SQLite และสร้าง schema รุ่นแรก
packages/shared/src/    Zod schemas และ TypeScript types ที่ใช้ร่วมกัน
n8n/                    Workflow ที่ import ได้ และ Docker Compose ทางเลือก
docs/                   คู่มือ API, อ่านโค้ด, ศึกษาวิดีโอ และสคริปต์พรีเซนต์
presentation/           สไลด์ภาษาไทย
tests/                  ตรวจ API ด้วย Hono และ SQLite จริงใน memory
```

## คำสั่งสำคัญ

```powershell
npm run typecheck
npm test
node n8n/validate-workflow.mjs
npm run build
npm start
```

หลัง build แล้ว `npm start` ให้ Hono เสิร์ฟทั้ง frontend และ API ที่ **http://localhost:3000** เหมาะกับการเดโมโดยเปิด server เดียว ค่าพัฒนาอนุญาต Origin ทั้ง 5173 และ 3000

## ขอบเขตและข้อจำกัด

**การทดลองบน Render Free:** `render.yaml` เก็บ SQLite ใน `/tmp` ข้อมูลบัญชี งาน บันทึก และสมาชิกหายได้เมื่อ service หลับ รีสตาร์ต หรือ deploy ใหม่ จึงไม่ควรชวนคนเก็บข้อมูลจริงบน URL นี้ การเก็บข้อมูลถาวรที่เตรียมไว้ใน repo คือ `deploy/render-paid.yaml` ซึ่งใช้ Render Starter และ persistent disk ต้องเปลี่ยนแผนบริการก่อนเปิดให้ใช้งานจริง หากต้องการคงค่าใช้จ่ายศูนย์ ต้องย้ายฐานข้อมูลไปบริการภายนอกที่มี Free Tier และทดสอบการย้ายข้อมูล/สำรอง/กู้คืนก่อนใช้งานจริง

นี่เป็นโปรเจกต์เรียนรู้ที่มีการตรวจสิทธิ์และทดสอบพฤติกรรมสำคัญ ไม่ได้อ้างว่าติดตั้งแล้วพร้อมรับระบบจริงทุกขนาด

- JWT มีอายุ 5 ชั่วโมง ต้อง login ใหม่เมื่อหมดอายุ ไม่มี refresh token
- Password reset ต้องตั้ง SMTP ก่อน ลิงก์มีอายุ 5 นาที การส่งทำงานแบบ async ใน process เดียว ไม่มี durable queue หาก server หยุดระหว่างรอส่งอาจต้องขอลิงก์ใหม่
- SMTP ยอมรับข้อความไม่ยืนยันว่าเข้า inbox และระบบยังไม่มี email verification ตอนสมัคร
- JWT ใน HttpOnly cookie ป้องกัน JavaScript อ่าน token โดยตรง แต่ไม่ได้กำจัดความเสี่ยงจาก XSS ทั้งหมด
- API key มีอายุ 30 วัน และใช้เฉพาะ API สำหรับ reminders ของผู้สร้าง key
- Auth rate limiter เก็บใน memory ของ server เดียว รีสตาร์ทแล้วนับใหม่ จึงไม่เหมาะกับหลาย instance โดยตรง
- SQLite เหมาะกับเดโมและระบบขนาดเล็ก มี additive migration ถึง schema รุ่น 6 โดยรักษาข้อมูลเดิม ก่อนอัปเกรดระบบจริงควรสำรองและตรวจการกู้คืน
- API รายการงานไม่มี pagination เหมาะกับข้อมูลจำนวนน้อย
- due tasks คืนได้สูงสุด 100 งานต่อครั้ง และประวัติแจ้งเตือนแสดง 100 รายการล่าสุด
- ประวัติแจ้งเตือนหมายถึง n8n รายงานว่า SMTP รับแล้ว ไม่ได้ยืนยันว่าอีเมลถึงกล่องผู้รับ
- การส่งอีเมลและบันทึกประวัติไม่ใช่ transaction เดียวกัน จึงยังมีโอกาสส่งซ้ำหากบันทึกล้มเหลวหลังส่ง หรือรัน workflow พร้อมกัน
- Workflow เตรียมไว้ให้ import แต่ต้องตั้ง API key และ SMTP เอง ไม่มี credential จริงอยู่ในไฟล์
- คลิป API/Auth ศึกษาจากคำบรรยายอังกฤษอัตโนมัติครบทั้งคลิปและ repo ผู้สอน ส่วนคลิป Monorepo ใช้หน้าอธิบาย รายการบท และ repo ผู้สอน เพราะไม่มี transcript ให้ดึง ดูรายละเอียดที่ `docs/video-study.md`

ก่อนใช้งานจริงควรจัด HTTPS, `NODE_ENV=production`, `APP_ORIGIN=https://...`, ปิดบัญชีเดโม, จัด secrets และสำรองฐานข้อมูล ทดสอบกู้คืน เพิ่ม monitoring และ migration รวมทั้งประเมิน password hashing/rate limiting ตามสภาพแวดล้อมจริง

ค่า HOST เริ่มต้นคือ `127.0.0.1` ถ้า n8n อยู่ใน Docker ให้ดูวิธีเชื่อมเครือข่ายในคู่มือ n8n ก่อนเปลี่ยน HOST
