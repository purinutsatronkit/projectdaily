# วิธีนำหน้าสไลด์ที่แก้ไปใช้

ไฟล์ PowerPoint ชุดนี้มีเฉพาะ 13 หน้าที่แก้หรือเพิ่ม จึงไม่มีหน้าปกใหม่ ใช้เลขหน้าใน PDF ต้นฉบับ 16 หน้าเป็นจุดอ้างอิง และมีข้อความกำกับที่ท้ายสไลด์ทุกหน้า

| หน้าในไฟล์ใหม่ | ใช้กับ PDF เดิม | เนื้อหา |
| --- | --- | --- |
| 1 | เพิ่มหลังหน้า 2 | ภาพหน้าจอ Dashboard จริง และสิ่งที่ผู้ใช้ทำได้ |
| 2 | แทนหน้า 3 | สถาปัตยกรรม พร้อมทิศทาง n8n เรียก Hono และ Hono ส่งอีเมลผ่าน Gmail |
| 3 | แทนหน้า 4 | โครงสร้าง monorepo และตำแหน่ง shared, n8n, docs ที่ถูกต้อง |
| 4 | เพิ่มหลังหน้า 6 | ตัวอย่าง SQL จำกัดสิทธิ์ให้อ่านหรือแก้เฉพาะงานของตนเอง |
| 5 | แทนหน้า 7 | JWT, cookie และการเพิกถอน session ในฐานข้อมูล |
| 6 | แทนหน้า 8 | เปรียบเทียบ JWT, API key และ reset token พร้อมอายุและวิธีเก็บ |
| 7 | แทนหน้า 10 | Token ใช้ครั้งเดียว และขอบเขต transaction ตอนเปลี่ยนรหัสผ่าน |
| 8 | แทนหน้า 11 | ภาพหน้าตั้งรหัสผ่านใหม่จริง และการลบ token จาก URL เมื่อเปิดหน้า |
| 9 | แทนหน้า 12 | การตั้ง Gmail SMTP และขอบเขตของสิ่งที่ทดสอบแล้ว |
| 10 | แทนหน้า 13 | การตรวจ request และจำนวน rate limit ตามโค้ดปัจจุบัน |
| 11 | แทนหน้า 14 | ตารางสิทธิ์ของ session และ API key พร้อมสถานะของงาน |
| 12 | แทนหน้า 15 | HTTP method, API route และความหมายของ error status |
| 13 | เพิ่มหลังหน้า 16 | ผลทดสอบ 54 ข้อ และส่วนที่ยังต้องลองกับบริการจริง |

## วิธีจัดเข้าชุดเดิม

1. เปิด PowerPoint ชุดนี้ แล้วคัดลอกหน้าที่ต้องการไปแทนหรือแทรกตามตาราง
2. หน้าเดิม 1, 2, 5, 6, 9 และ 16 ยังใช้ต่อได้
3. เมื่อเพิ่มครบ 3 หน้า ชุดรวมจะมี 19 หน้า ปรับเลขหน้าในชุดรวมให้ต่อเนื่องก่อนนำเสนอ
4. อ่านช่อง Notes ของแต่ละหน้า จะมีคำอธิบายสำหรับพูดและตอบคำถาม โดยเฉพาะความแตกต่างระหว่าง JWT กับ session และการยอมรับอีเมลของ SMTP กับการเข้า inbox

หากแก้ใน Canva ให้อัปโหลดไฟล์ PowerPoint นี้แล้วเลือกหน้าที่ต้องการใช้ อาจต้องขยับข้อความหรือฟอนต์เล็กน้อยหลังนำเข้า เพราะต้นฉบับที่ได้รับเป็น PDF และหน้าที่แก้สร้างใหม่เป็นองค์ประกอบที่แก้ไขได้

ผลทดสอบในสไลด์อ้างอิงการทดสอบที่บันทึกไว้ของโครงการ ไม่ได้หมายความว่าทดลองส่ง Gmail เข้า inbox หรือรัน n8n จริงแล้ว
